# Global Agent Guidelines

Aim for momentum: small verified changes landed on main, in few turns and lean context.

- Public GitHub replies (issues or PRs): state what changed, when it ships, and ask the reporter to test and report back — never tell users that we cannot run tests locally or lack hardware. Keep hardware-untested caveats strictly in internal maintainer reports and never claim unrun hardware tests as passed.
- Clean up build and workspace disk space before finishing: never leave private per-worktree build caches (`target/`, `build/`, `.cxx/`, `.gradle/`, or temp/scratch directories) behind. Reuse the project's shared target pool (`CARGO_TARGET_DIR`, Rubylight: `python tools/dev.py cargo -- <args>`, Gradle via `tools/build_lock.py --lane gradle -- ... --no-daemon`), or delete scratch target/temp dirs in a `try`/`finally` block before reporting done. Always kill any helper subagents you spawned before exiting; coordinators should kill finished isolated-workspace workers immediately after landing their commits and check free disk space before launching heavy parallel builds.
- Work autonomously; ask only when a consequential decision cannot be inferred. Check each premise against `origin/main`, a measurement, or official online documentation when a device is not local. Keep scope focused; preserve unrelated work.
- Native Antigravity routing by default: batch independent searches, reads and edits in parallel in one turn; read only the line ranges needed; filter command output to errors and tails. Delegate broad read-only surveys to the `research` subagent; use `/swarm` only when explicitly requested or already active. Never switch harnesses by default.
- Cross-harness opt-in (NEVER by default): only when the user explicitly asks for an independent Claude Code review or task (e.g. an Opus 5.5 second opinion), run `python "$HOME/.claude/tools/worker.py" <read|write|code|review> --harness claude --dir <checkout> "<brief>"` (add `--effort xhigh` for deep Opus reviews; read/review enforce read-only via `--disallowedTools` and a clean `review` unlocks the push gate).
- Laptop CPU & GPU offload: when working on the PC and offloading builds, tests, or GPU/e2e runs to the laptop (`ramaz@192.168.4.12`), use `python "$HOME/.claude/tools/laptop.py" status|run|check|clean`. It checks locks (`BUILD-LOCK`/`LAPTOP-LOCK`), runs in the laptop's Interactive desktop session (so GUI/GPU/host tests work), cleans its detached worktree automatically, and preserves exit code 3 (AMD encoder hang — investigate, never retry).
- Zero firewall prompts: bind test and ad-hoc dev servers to loopback (`127.0.0.1` / `localhost` / `[::1]`) and keep Cargo builds in the warm target pool (`python tools/dev.py cargo -- <args>`).
- Review gate and landing: verify with the narrowest fitting check and add a regression test where useful. Before landing >150 code lines or changes in concurrency, lifetime, protocol, decoder or release code, run an independent review (`python "$HOME/.claude/tools/worker.py" review --dir <checkout> "<brief>"`, which uses Antigravity Carbon in plan mode by default, or `--harness claude` when explicitly asked for Opus); a `PreToolUse` hook holds unreviewed pushes to `main`. Commit only the task's changes with a conventional message, then land with `python "$HOME/.claude/tools/land.py" --repo <checkout> --check "<affected checks>"`. Never commit secrets, force-push, rewrite shared history, open PRs, tag or publish unless asked.
- Periodic hygiene: `python "$HOME/.claude/tools/task.py" caches` prunes idle Cargo targets; `python "$HOME/.claude/tools/task.py" sessions [--gemini-days N] --apply` prunes old Claude and Antigravity session bloat safely.
- Report concisely: result, decisions, verification, limits; mark each part of the request done, not done (why) or not verified.
