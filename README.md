# claude-code-setup

Shared working rules for Claude Code, Codex, OpenCode and Antigravity, optional Haiku and DeepSeek helper definitions, plus model and compaction settings. Agents work autonomously, with two fixed points: a stronger model is asked about the choices, and an independent reviewer sees a larger code change before it lands. A subagent never runs on the costliest model.

## Install

Requires Python 3.8+ and Claude Code. Run `python install.py --dry-run`, then `python install.py`.

The installer copies `claude/CLAUDE.md` into `~/.claude` (or `CLAUDE_CONFIG_DIR`), merges `claude/settings.json`, and creates `personal.md` from its example only if absent. It writes the same rules, with `personal.md` inlined, for each other agent whose config directory exists: Codex (`~/.codex/AGENTS.md` or `CODEX_HOME`), OpenCode (`~/.config/opencode/AGENTS.md`) and Antigravity (`~/.gemini/GEMINI.md`). It also merges `opencode/opencode.json` into OpenCode's global config, accepting JSONC comments and trailing commas; changed configs are written as JSON. Replaced files are backed up under `~/.claude/backups/`. Orca's Claude profiles import `~/.claude`, so the installer writes there even when run from an Orca Claude session.

The installer also copies each harness's `scout`, `runner` and `mechanic` helper definitions into its agents directory: `~/.claude/agents`, OpenCode's `agents`, `~/.codex/agents` and `~/.gemini/config/agents`. Each helper runs on that harness's own cheap model. A shared rule sends broad searches, builds, test runs, the push chore and fully specified edits to these helpers where they exist; everything else stays with the main agent.

A second rule moves volume work off the costlier models, after Spotify's [bulk-reader and code-writer routing](https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90): bulk reading and scaffolding go to a DeepSeek V4.1 Flash worker started through Orca's orchestration (`orca orchestration worker-start --agent opencode --model opencode-go/deepseek-v4.1-flash`), and only its report comes back. As there, editing, debugging and design stay with the main agent, which reads the exact range itself before changing it. Orca cannot pass OpenCode a reasoning level and starts its workers at `high`, so `opencode/opencode.json` sets `reasoning_effort: max` in that model's request body. That holds on every launch path and also overrides a variant picked in OpenCode; use `settings.reasoningEffort` instead for a default a variant can still lower. A third rule says what a brief must carry, after Spotify's notes on [context engineering for background coding agents](https://engineering.atspotify.com/2025/11/context-engineering-background-coding-agents-part-2): the end state and its check, the context up front, an example, when not to act, and one change per brief.

An Orca worker reports to the session that started it, which a subagent cannot receive. For that case, and for a report needed in the same turn, the installer copies `claude/tools/deepseek.py` to `~/.claude/tools` where OpenCode is set up. `python ~/.claude/tools/deepseek.py read "<brief>"` (or `write`) runs the same model through `opencode run`, waits, and prints only the final report; a one-file question took 19 seconds here and a test skeleton 9. OpenCode's permission prompts are answered for it, so `read` changes nothing because it is told not to, not because it cannot. `--timeout` (900 seconds by default) ends the run with its child processes and exits with 124.

`claude/settings.json` sets `CLAUDE_CODE_SUBAGENT_MODEL` to `opus`, so a subagent started without a model no longer inherits Fable from a Fable session. In our transcripts of the four days to 2026-11-14 that was 20 general-purpose runs for $198 at list prices, about $10 a run against $8 on Opus, and no call had asked for Fable. The helpers keep the model in their definition and a `model` passed to the Agent tool still wins (both checked with `claude -p`), so the rules ask for `sonnet` or `haiku` on simple work. A fork always runs on its parent's model, hence the rule to brief a fresh agent there. If your main model is Sonnet or Haiku, change the value in `claude/settings.json` before installing, or subagents cost more than the session that starts them.

`claude/settings.json` also sets `advisorModel` to `fable`. Claude Code's [advisor tool](https://code.claude.com/docs/en/advisor) lets the working model ask a stronger one, which reads the whole conversation, at decision points; subagents inherit it. With Opus as the default subagent model, the work runs on Opus and Fable is asked where the plan matters. No setting forces a call, so a rule tells an agent on Opus to consult it on the choices of a task that changes behaviour: before committing to an approach (what to build, how far, which default, what to measure), when a fix did not work, and before declaring the work done. The setting cannot be limited to one main model, so a Fable session gets a Fable advisor too. Advisor tokens are not in a message's own usage totals; `tools/cost_report.py` lists the calls on a separate line at list prices ($1.62 a call in our first 32, each an uncached read of the conversation). Anthropic's page says they are billed at the advisor's rates, or to usage credits on some plans, so check your own usage before leaving it on.

Review came back on 2026-11-14 as a hook, not a workflow. `claude/agents/reviewer.md` (Opus, high effort, read-only) judges a diff against the request it was given, with a checklist ordered by what has escaped here: lifetimes and shutdown order, callers not updated, swallowed errors, edge cases, races, tests that pass without the change, and parts of the request quietly narrowed. A call into a vendor SDK it checks against the vendor's headers and samples, which the brief names or the build script unpacks, and what those cannot settle it lists for the author to test. `claude/hooks/review_gate.py` runs before every shell command and holds back a `git push` to `main` that carries 60 or more changed code lines the reviewer has not seen; prose and translations do not count. When the reviewer agent finishes, which it says with a last line `Reviewed: <repository>`, the hook notes every line the change adds or removes. That line is the reviewer's word for everything the checkout holds beyond `origin/main`, so a review of a part ends differently and unlocks nothing. Lines the note lacks count as fixes: up to 150 of them, and no more than the review saw, pass without a second review, for a day; more than that is held whatever the findings were. A rebase onto other people's edits of the same files changes nothing in that count. A command that commits and pushes at once is judged by everything the checkout holds beyond `main`, staged or not: its commit does not exist yet, and reading from the command text what it will take proved unsafe (a `;` in the message or a redirect was enough to count nothing). If that is held because other work lies in the tree, the message says to commit first and push in a command of its own, which is judged by the commits it pushes; one that merges, cherry-picks or reverts and pushes at once is told the same. The gate catches a push nobody reviewed; it is no lock against an agent set on getting past it, and a push it cannot read (a wrapper script, an alias) passes without a log line. A command that ends with the comment `# REVIEW_SKIP=<reason>` passes and is logged, for a change the user wants out at once; `CLAUDE_REVIEW_MIN_LINES` in the `env` of `settings.json` moves the threshold and 0 turns the gate off. Holds, passes on a review, skips and errors go to `~/.claude/review-gate.log`; a push under the threshold leaves no line. The reason is a replay on our own history: three Opus reviewers each got, blind, one commit that introduced a bug users reported that week. One named the shipped bug. One named it only after reading a later commit message, which does not count, but also found two other bugs in that commit that were fixed later the same day. The third missed its bug, an NVIDIA SDK call it said it could not check; given the path of the SDK's headers in a second blind run, it named that crash first (eleven minutes on a 2,000-line change). The others took two to four minutes.

Sessions clean up through `claude/tools/task.py`, installed to `~/.claude/tools`. `task.py open <task>` makes one folder per task below the machine's artifact folder and prints it; builds and logs go in there. What a task makes elsewhere it records: `task.py add <task> dir <path>`, `process <pid>`, `remote <host> <path>` or `command "<what puts it back>"`. `task.py close <task>` undoes those, newest first, and deletes the folder; if one cannot be undone the folder stays and says which. Only `close` deletes, and only what the task itself can have made. A folder elsewhere must lie in the temp folder or a root the machine file names and hold none of those nor the artifact folder, be no link, hold no checkout anywhere inside and nothing from the keep list, and have been created after the task was opened; Linux keeps no creation time, so there it must be `<root>/<task>` or lie in it, counted from the nearest root when one root lies in another. A process is ended, with what it started, only while it has the start time it was recorded with, so a reused process number is left alone. A folder on another machine must be `<that host's root>/<task>` or lie in it. The task's own folder stays while it holds a checkout, and on Windows while a shell or a program still uses it, and nothing in it is deleted before that is known; on Linux a folder in use is deleted all the same. A link in the artifact folder is no task folder. The record is checked again at close, with the task's name taken from its folder, against honest mistakes; it is no defence against someone who edits `task.json`, whose `command` entries run as written. `task.py sweep` lists the folders that look finished (the worktree is gone, or nothing touched folder or worktree for three days), the worktrees that closed tasks left, and the folders it knows nothing about; it deletes nothing, and a worktree is never removed by this tool. A `SessionStart` hook runs `task.py daily`, which adds one line to a new session at most once a day when something looks finished. `~/.claude/machine.json`, created from `claude/machine.example.json` when absent, names the artifact folder, further roots, a keep list (never deleted, with what the entries hold and what holds them) and the other machines.

`subagentPromptCacheTtl` is `1h`: general-purpose subagents pause for builds, and in 1.8 days 59% of their cache-write tokens were whole contexts written again after a pause of 5 to 60 minutes.

The installer also copies `claude/hooks/read_streak.py` to `~/.claude/hooks` and registers it as a `PostToolBatch` hook in `settings.json`, run by the Python that ran the installer (rerun it if that Python moves). The hook counts turns in a row that made one read-only call and, at the third and every sixth after, adds one line telling the model to batch its reads or hand the survey to a helper (in a subagent, to `scout` or `deepseek.py`). It never blocks a call, skips the cheap helper agents, and `CLAUDE_READ_STREAK` sets the first nudge (0 turns it off). The reason is in our own transcripts (`tools/context_fill.py`, four days to 2026-11-13): 80 to 90% of turns made a single tool call, and streaks of three or more turns with one read-only call each were 19% of main-chat and 37% of subagent spend, while whole-file reads of over 350 lines were 2% of what fills the main context. So the hook watches turns, not file size.

Edit templates here before reinstalling. Keep machine-specific paths in `~/.claude/personal.md`, which Claude imports and the other agents get inlined; rerun the installer after editing it. Existing hooks, credentials and allow permissions are preserved. The installer removes deny permissions, the old desktop skill blocks, OpenCode helper routing and the disabled general agent override. It also removes the retired Opus helper definitions when their contents still match this setup; user replacements are preserved.

## Contents

- `claude/CLAUDE.md`: autonomy, focused changes, verification, Git landing, lean context, delegation (helpers, DeepSeek workers through Orca or `deepseek.py`, subagent models, the advisor, review, briefs) and temporary-output rules.
- `claude/agents/`: Haiku scout, runner and mechanic definitions, and the Opus reviewer.
- `claude/hooks/read_streak.py`: the nudge after read-only turns of one call each.
- `claude/hooks/review_gate.py`: holds back an unreviewed push to main and notes when the reviewer ran.
- `opencode/agents/`: DeepSeek V4.1 Flash scout, runner and mechanic definitions, without deny permissions.
- `codex/agents/`: GPT-6 Luna scout, runner and mechanic definitions at medium reasoning effort.
- `antigravity/agents/`: Gemini Flash scout, runner and mechanic definitions.
- `claude/tools/deepseek.py`: a DeepSeek read or scaffolding run that waits and prints only the report.
- `claude/tools/task.py`: one folder per task, a record of what a task leaves elsewhere, and the close that undoes it.
- `claude/machine.example.json`: where task folders go on a machine and what is never deleted.
- `claude/settings.json`: output, effort and compaction settings, Opus as the default subagent model, Fable as the advisor and a one-hour cache for subagents.
- `opencode/opencode.json`: DeepSeek V4.1 Flash as OpenCode's default model at maximum reasoning, and context limits for Anthropic models, Gemini 4 Argon and Kimi K3.1 Pro.
- `test_install.py`: installer migration, backup and repeat-install checks, and the behaviour of the hooks, the DeepSeek tool and the task tool (`python -m unittest -v`).
- `tools/cost_report.py`: optional historical transcript analysis, with advisor calls listed apart; it does not control the workflow.
- `tools/context_fill.py`: what fills Claude Code contexts (tool results by tool, shell output by command kind) and where the turns go (tool calls per turn, spend in read-only streaks).
- `tools/opencode_cost.py`: where OpenCode's Anthropic spend goes: cost split, context sizes, what fills the context, and the 5-minute vs 1-hour cache trade-off.
