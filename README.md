# claude-code-setup

Shared working rules for Claude Code, Codex, OpenCode and Antigravity, `oc.py`, which hands work to the flat-rate OpenCode models (DeepSeek V4.1 Flash, GLM 5.3), plus model and compaction settings. Agents work autonomously toward small verified changes on main, one issue per chat, and an independent reviewer sees a larger code change before it lands. A subagent never runs on the costliest model.

## Install

Requires Python 3.8+ and Claude Code. Run `python install.py --dry-run`, then `python install.py`.

The installer copies `claude/CLAUDE.md` into `~/.claude` (or `CLAUDE_CONFIG_DIR`), merges `claude/settings.json`, and creates `personal.md` from its example only if absent. It writes the same rules, with `personal.md` inlined, for each other agent whose config directory exists: Codex (`~/.codex/AGENTS.md` or `CODEX_HOME`), OpenCode (`~/.config/opencode/AGENTS.md`) and Antigravity (`~/.gemini/GEMINI.md`). It also merges `opencode/opencode.json` into OpenCode's global config, accepting JSONC comments and trailing commas; changed configs are written as JSON. Replaced files are backed up under `~/.claude/backups/`. Orca's Claude profiles import `~/.claude`, so the installer writes there even when run from an Orca Claude session.

The installer copies the `scout`, `runner` and `mechanic` helper definitions of OpenCode, Codex and Antigravity into their agents directories, each on that harness's cheap model. Claude Code's Haiku helpers were retired on 2026-11-20: its rule sends that work to `oc.py` instead.

Since the evening of 2026-11-20 (user: "glm5.3 xhigh especially is very smart. deepseek max is unlimited use practically ... refactor the workflow completely") Claude decides, writes fixes up to ~60 lines and lands, and `oc.py` runs the rest on the flat-rate OpenCode Go subscription: `read` and `write` on DeepSeek V4.1 Flash at maximum reasoning, `code` and `review` on GLM 5.3 with `reasoning_effort: xhigh` in `opencode.json` (GLM has no variants in OpenCode; the gateway accepts an invalid effort without error, so whether xhigh is honoured is not visible). DeepSeek Pro is not used. The 1017 snapshot of V4.1 Flash is not offered by OpenCode Go or Zen.

`python ~/.claude/tools/oc.py <read|write|code|review> --dir <checkout> "<brief>"` runs `opencode run`, waits, and prints only the final report, so the worker's reads and code never enter the caller's context. `review` gives GLM the reviewer agent's own instructions, and a clean finish (`Reviewed: <path>`) unlocks the push hook as that agent's run does. OpenCode's permission prompts are answered for it, so `read` and `review` change nothing because they are told not to. `--timeout` (1800 s) ends the run with its child processes and exits with 124; `--model flash|glm|glm-flash|<id>` overrides the mode's model.

`claude/settings.json` sets `CLAUDE_CODE_SUBAGENT_MODEL` to `opus`, so a subagent started without a model no longer inherits Fable from a Fable session. In our transcripts of the four days to 2026-11-14 that was 20 general-purpose runs for $198 at list prices, about $10 a run against $8 on Opus, and no call had asked for Fable. The helpers keep the model in their definition and a `model` passed to the Agent tool still wins (both checked with `claude -p`), so the rules ask for `sonnet` or `haiku` on simple work. A fork always runs on its parent's model, hence the rule to brief a fresh agent there. If your main model is Sonnet or Haiku, change the value in `claude/settings.json` before installing, or subagents cost more than the session that starts them.

`claude/settings.json` also sets `CLAUDE_CODE_DISABLE_ARTIFACT` to `1`. The Artifact tool was 13k of the 48k tokens a `claude -p` probe session starts with (35k without it), paid again on every turn of every main chat and general-purpose agent, and it was called twice in the 14 days of transcripts to 2026-11-19 (1,144 sessions). At that week's 33,000 main-chat and general-purpose turns that is about $135 a week at list prices, and 13k more room before compaction. To have artifacts back, set it to `0` here and reinstall (probed: 47.6k again); the installer puts the template's value back over an edit made only in `~/.claude/settings.json`. Settings reload in running sessions: the session that installed it lost its Artifact tools and its scratchpad directory on the spot, and Orca passes it on to its profile at its next sync. Workflows (2k tokens) were measured the same way and stay on, since they are used.

General-purpose agents carried it too: with no other settings, one started at 29.5k tokens with the tool and 17.5k without (`--setting-sources local`). The same probe then found about 4k more that sessions carried without using (35.1k to 30.3k for a main chat, 25.2k to 22.0k for a general-purpose agent, both measured with these settings on 2026-11-19):
- `skillOverrides`: skills the model never invoked in those 14 days. The ones you type (`simplify`, `init`, `security-review`, `fewer-permission-prompts`) are `user-invocable-only`, so their slash commands stay; `code-review` is off (below). Rare model-triggered ones show only their name (`name-only`), and the Docs skill is `off` along with its connector. In one probe, setting skills to `off` made the prompt larger, while the two softer values shrink it.
- `disableClaudeAiConnectors`: the claude.ai Claude Docs connector (1.7k of tools and instructions) served one session in 14 days. The `ENABLE_CLAUDEAI_MCP_SERVERS` variable does nothing from `settings.json`, because it is read before settings apply (probed).
- `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS`: Explore and Plan duplicate `oc.py read` and the main chat's own planning.

`CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` stays unset. It would save 0.4 to 0.7k and drop two built-in bullets that contradict the landing rule ("Commit or push only when the user asks", "If on the default branch, branch first"), but a probe commit made with it lost its `Signed-off-by` trailer, while the control run kept it.

To restore one, set the skill to `on`, the variable to `0` or the setting to `false` here, and reinstall. Text added during a session was left alone: the Concise output style's reminder after each tool result costs about $33 a week to carry but keeps answers short, the read-streak nudge about $10, and the task-notification preambles about $27 come from Claude Code itself.

A third pass on 2026-11-19 kept only what agents use: a main chat went from 30.3k to 21.2k tokens, a general-purpose agent from 22.0k to 14.5k.
- `CLAUDE_CODE_USE_POWERSHELL_TOOL=0` (3.6k): the Bash tool made 59k calls in 14 days against PowerShell's 15k. It runs PowerShell as `pwsh -NoProfile -Command` or `-File`, which `personal.md` now says (probed). The helper agents' tool lists no longer name PowerShell.
- Every skill but `orca-cli` shows only its name (3.0k). `orca-cli` keeps its description because its triggers ("hand off", "Orca worktree") are not in its name.
- `ScheduleWakeup` (1.7k: `/loop`'s self-paced mode, 3 calls in 14 days) and `ReportFindings` (0.8k: used only by `/code-review`, not typed in 14 days) are denied, which takes them out of the prompt; `code-review` is off with it, since the reviewer agent does that job. The installer keeps the template's `permissions.deny` and still removes every other deny rule, so a tool removed from that list here comes back on the next install. To get `/code-review` back, set it to `user-invocable-only` and drop `ReportFindings` from that list.
- `CLAUDE.md` went from 6.8 to 5.3 KB with the same rules. Cut: the details that `land.py` and the hooks print themselves, and the reasons for rules a hook now enforces.

Kept, because they are used: Workflow (2.1k, 75 calls in 14 days), memory (1.2k), the Concise output style (0.5k) and the claude-code-guide agent.

The advisor (`advisorModel: fable`, since 2026-11-14) was removed on 2026-11-20 at the user's word. Its tool asks every Opus chat for at least two calls per task, each waiting while Fable reads the whole transcript, and the user found the work slowed and congested. The installer deletes `advisorModel` and the `advisor_guard.py` hook entry; the script stays in `~/.claude/hooks` for sessions started before.

Review came back on 2026-11-14 as a hook, not a workflow. `claude/agents/reviewer.md` (Opus, high effort, read-only) judges a diff against the request it was given, with a checklist ordered by what has escaped here: lifetimes and shutdown order, callers not updated, swallowed errors, edge cases, races, tests that pass without the change, and parts of the request quietly narrowed. A call into a vendor SDK it checks against the vendor's headers and samples, which the brief names or the build script unpacks, and what those cannot settle it lists for the author to test. `claude/hooks/review_gate.py` runs before every shell command and holds back a `git push` to `main` that carries 150 or more changed code lines the reviewer has not seen; prose and translations do not count. When the reviewer agent finishes, which it says with a last line `Reviewed: <repository>`, the hook notes every line the change adds or removes. That line is the reviewer's word for everything the checkout holds beyond `origin/main`, so a review of a part ends differently and unlocks nothing. Lines the note lacks count as fixes: up to 150 of them, and no more than the review saw, pass without a second review, for a day; more than that is held whatever the findings were. A rebase onto other people's edits of the same files changes nothing in that count. A command that commits and pushes at once is judged by everything the checkout holds beyond `main`, staged or not: its commit does not exist yet, and reading from the command text what it will take proved unsafe (a `;` in the message or a redirect was enough to count nothing). If that is held because other work lies in the tree, the message says to commit first and push in a command of its own, which is judged by the commits it pushes; one that merges, cherry-picks or reverts and pushes at once is told the same. The gate catches a push nobody reviewed; it is no lock against an agent set on getting past it, and a push it cannot read (a wrapper script, an alias) passes without a log line. A command that ends with the comment `# REVIEW_SKIP=<reason>` passes and is logged, for a change the user wants out at once; `CLAUDE_REVIEW_MIN_LINES` in the `env` of `settings.json` moves the threshold and 0 turns the gate off. Holds, passes on a review, skips and errors go to `~/.claude/review-gate.log`; a push under the threshold leaves no line. The reason is a replay on our own history: three Opus reviewers each got, blind, one commit that introduced a bug users reported that week. One named the shipped bug. One named it only after reading a later commit message, which does not count, but also found two other bugs in that commit that were fixed later the same day. The third missed its bug, an NVIDIA SDK call it said it could not check; given the path of the SDK's headers in a second blind run, it named that crash first (eleven minutes on a 2,000-line change). The others took two to four minutes. The reviewer reads in few turns: it writes the whole diff to a file and reads it in large parts, and opens the code around the hunks in one turn of parallel calls. Before that (7 days to 2026-11-19, 174 reviews) 85% of its turns made a single call, turns that only read were 78% of its spend, and a review took a median of 31 turns and $2.28.

Sessions clean up through `claude/tools/task.py`, installed to `~/.claude/tools`. `task.py open <task>` makes one folder per task below the machine's artifact folder and prints it; builds and logs go in there. What a task makes elsewhere it records: `task.py add <task> dir <path>`, `process <pid>`, `remote <host> <path>` or `command "<what puts it back>"`. `task.py close <task>` undoes those, newest first, and deletes the folder; if one cannot be undone the folder stays and says which. Only `close` deletes, and only what the task itself can have made. A folder elsewhere must lie in the temp folder or a root the machine file names and hold none of those nor the artifact folder, be no link, hold no checkout anywhere inside and nothing from the keep list, and have been created after the task was opened; Linux keeps no creation time, so there it must be `<root>/<task>` or lie in it, counted from the nearest root when one root lies in another. A process is ended, with what it started, only while it has the start time it was recorded with, so a reused process number is left alone. A folder on another machine must be `<that host's root>/<task>` or lie in it. The task's own folder stays while it holds a checkout, and on Windows while a shell or a program still uses it, and nothing in it is deleted before that is known; on Linux a folder in use is deleted all the same. A link in the artifact folder is no task folder. The record is checked again at close, with the task's name taken from its folder, against honest mistakes; it is no defence against someone who edits `task.json`, whose `command` entries run as written. `task.py sweep` lists the folders that look finished (the worktree is gone, or nothing touched folder or worktree for three days), the worktrees that closed tasks left, and the folders it knows nothing about; it deletes nothing, and a worktree is never removed by this tool. A `SessionStart` hook runs `task.py daily`, which adds one line to a new session at most once a day when something looks finished. `~/.claude/machine.json`, created from `claude/machine.example.json` when absent, names the artifact folder, further roots, a keep list (never deleted, with what the entries hold and what holds them) and the other machines.

A memory folder is shared with a second machine by `claude/tools/memory_sync.py`, run by hand on the machine that can reach the other over ssh; nothing starts it, so edits made on the other machine arrive when it is next run. `machine.json` names the pairs under `"memory"`: the local folder, the host and its folder there, and files each machine keeps as its own. It compares every file with the copy both machines had after the last run. A file changed or new on one machine is copied to the other; one changed on both is merged by line when the changes lie apart, and otherwise both stay as they are and the file is named, with the other machine's copy saved beside the tool's state to read before `--mine` or `--theirs` settles it. A file deleted on one machine is named and left alone on the other, never copied back and never deleted. `MEMORY.md` is merged by the file each line points to: a pointer stays on a machine for as long as that machine has the file, no machine gets a pointer to a file it lacks, and where both machines changed the same pointer or both the headings it is named like any other file. Who saved a file and when does not count as a change, nor do line endings. It writes the other machine's files beside its folder first and moves each in only while the file it replaces is still the one it read, checks this machine's files the same way, and leaves a file that changed during the run for the next one. Before a run writes it saves both sides (the last 20 backups stay) and its plan, so that a run cut off half-way is finished by the next. It stops without writing when the other machine is away, or when a folder or an index holds less than half of what the last run left; when that loss is meant, `--meant` lets one run pass, which names the deleted files and leaves them on the machine that still has them.

`subagentPromptCacheTtl` is `1h`: general-purpose subagents pause for builds, and in 1.8 days 59% of their cache-write tokens were whole contexts written again after a pause of 5 to 60 minutes.

On 2026-11-20 the line count for a review rose from 60 to 150, and Opus, Fable and Sonnet compact at 300k tokens instead of 400k (the user's sweet spot) (`modelSettings`, which reaches subagents on those models too); the reviewer keeps 400k in its own definition, since a long diff would otherwise be compacted mid-review. In the four days before, the reviewer cost about $314 over 152 runs, 79% of it in turns that only read, and how many defects it caught that CI would have missed is not measured, so the higher count is a trial. In the same days two main chats carried 72% of all main-chat turns, at a median 250k to 300k tokens per turn against a first turn of 34k: so the rules now say one issue per chat, and a fix of up to about 60 lines is made in the main chat rather than handed to an agent.

Later that day the rules were cut back to a clean state (6.0 KB to 2.7 KB), since the user found that the rules had slowed the work: the advisor, the DeepSeek routing rule, the helper routing, the brief template and the `task.py` ritual went; landing with `land.py`, the review hook, the read-streak hook (one-call turn streaks fell from 19% to 7% of main-chat spend and from 37% to 24% of agents' since 11-13) and the fresh-checkout hook stayed. The slowdown began in the week of Nov 2, before most of that machinery, so faster work from the cut is not proven.

Auto memory has been off since the evening of 2026-11-20 (`autoMemoryEnabled: false`), at the user's request for a cleaner state. Its token cost was small (the index was about 1k tokens a turn, memory files 0.2% of what was read); its cost was the months of recorded decisions that kept steering new work after the user had moved on, such as keeping every setting. A lasting rule now goes into a project's AGENTS.md or `personal.md`, where the user sees it change; the facts agents cannot re-derive (device access, what must never be touched, a secret's location) moved to `personal.md`. `memory_sync.py` stays installed for anyone who turns memory back on.

The installer also copies `claude/hooks/read_streak.py` to `~/.claude/hooks` and registers it as a `PostToolBatch` hook in `settings.json`, run by the Python that ran the installer (rerun it if that Python moves). The hook counts turns in a row that made one read-only call and, at the third and every sixth after, adds one line telling the model to batch its reads or hand the survey to a helper (in a subagent, to `scout` or `deepseek.py`). It never blocks a call, skips the cheap helper agents, and `CLAUDE_READ_STREAK` sets the first nudge (0 turns it off). The reason is in our own transcripts (`tools/context_fill.py`, four days to 2026-11-13): 80 to 90% of turns made a single tool call, and streaks of three or more turns with one read-only call each were 19% of main-chat and 37% of subagent spend, while whole-file reads of over 350 lines were 2% of what fills the main context. So the hook watches turns, not file size.

A second `SessionStart` hook, `claude/hooks/fresh_checkout.py`, brings the session's checkout up to its remote branch: when it is on `main` or `master`, holds no commits of its own, no edits to tracked files (edits inside a submodule do not count), no merge or rebase under way, and no other live Claude Code session works in it (one may be building or releasing from it), it fetches and fast-forwards; otherwise, when it is behind, it tells the session in one line to read `origin/main` instead. It never merges, stashes or resets, and `CLAUDE_FRESH_CHECKOUT=0` turns it off. The reason: the Rubylight checkout most sessions start in sat 26 commits behind on 2026-11-15, so sessions loaded an AGENTS.md with rules the user had withdrawn a day earlier, and one search of old code told the user that a feature released the day before was not ours. Claude Code loads `CLAUDE.md` and `AGENTS.md` before this hook runs (probed), so the session it updates is told which of them changed, and the next one loads them current.

Edit templates here before reinstalling. Keep machine-specific paths in `~/.claude/personal.md`, which Claude imports and the other agents get inlined; rerun the installer after editing it. Existing hooks, credentials and allow permissions are preserved. The installer removes deny permissions other than the template's tool denies, the old desktop skill blocks, OpenCode helper routing and the disabled general agent override. It also removes the retired Opus helper definitions when their contents still match this setup; user replacements are preserved.

`claude/tools/land.py` turns the landing chore into one call. Before it, a push to `main` took about seven git and `gh` calls (fetch, status, rebase, log, push, then CI polling), with 79 pushes in two days on 2026-11-13 and 14 (counted from transcripts). It fetches `origin/main`, rebases onto it (never with a stash: tracked edits must be committed first), runs `--check` only when the rebase brought in other commits, asks `review_gate.py` about the exact commit as if it were a push command, pushes that commit, and when `main` moved meanwhile fetches, rebases and asks again, three times at most. It never force-pushes. A failed or interrupted check leaves the checkout rebased and makes every later run check again until one passes; submodules the rebase moved are brought along when they sat at the old commit. Its exit code says where it stopped: 0 landed or nothing to land, 1 usage or checkout problem, or CI not readable, not started or still running, 2 rebase failed (aborted, checkout unchanged), 3 check failed or still owed, 4 held by the review gate, 5 fetch or push failed, 6 CI failed. Helper agents pass `--agent <type>` so a hold tells them to report back instead of retrying. `--watch` waits for the commit's push-triggered CI runs, one `gh` call a minute, and prints the failed jobs' log tails; `--ci <sha>` does only that. Outside Claude Code (`CLAUDECODE` unset) the gate is not asked, since the hook does not guard those agents either.

## Contents

- `claude/CLAUDE.md`: momentum, verification, Git landing, one issue per chat and the issue batch, helper routing, lean context, agents and review; a test keeps it under 3 KB.
- `claude/agents/reviewer.md`: the review instructions, used by `oc.py review` and by the Opus agent for a second review on request.
- `claude/hooks/read_streak.py`: the nudge after read-only turns of one call each.
- `claude/hooks/review_gate.py`: holds back an unreviewed push to main and notes when the reviewer ran.
- `claude/hooks/fresh_checkout.py`: fast-forwards a clean checkout on main at session start, or says it is behind.
- `opencode/agents/`: DeepSeek V4.1 Flash scout, runner and mechanic definitions, without deny permissions.
- `codex/agents/`: GPT-6 Luna scout, runner and mechanic definitions at medium reasoning effort.
- `antigravity/agents/`: Gemini Flash scout, runner and mechanic definitions.
- `claude/tools/oc.py`: hands a read, write, code or review task to DeepSeek V4.1 Flash or GLM 5.3 through OpenCode, waits and prints only the report.
- `claude/skills/issue-batch/`: a list of issues through Orca: one GLM 5.3 code worker per issue, one DeepSeek builder that cherry-picks the fixes and runs the gate once, one GLM review of the integrated range and one landing.
- `claude/tools/task.py`: one folder per task, a record of what a task leaves elsewhere, and the close that undoes it.
- `claude/tools/memory_sync.py`: keeps a memory folder the same on this machine and one other, both ways, over ssh.
- `claude/machine.example.json`: where task folders go on a machine and what is never deleted.
- `claude/settings.json`: output, effort and compaction settings, auto memory off, Opus as the default subagent model, a one-hour cache for subagents.
- `opencode/opencode.json`: DeepSeek V4.1 Flash as OpenCode's default model at maximum reasoning, and context limits for Anthropic models, Gemini 4 Argon and Kimi K3.1 Pro.
- `test_install.py`: installer migration, backup and repeat-install checks, and the behaviour of the hooks, the DeepSeek tool and the task tool (`python -m unittest -v`).
- `tools/cost_report.py`: optional historical transcript analysis, with advisor calls listed apart; it does not control the workflow.
- `tools/context_fill.py`: what fills Claude Code contexts (tool results by tool, shell output by command kind) and where the turns go (tool calls per turn, spend in read-only streaks).
- `claude/tools/land.py`: lands a checkout's commits on the remote `main` in one call (fetch, rebase, check when `main` moved, review gate, push, retry on a race) and optionally waits for their CI.
- `tools/user_messages.py`: the messages you typed, one per line, to find where the agents cost you corrections.
- `tools/opencode_cost.py`: where OpenCode's Anthropic spend goes: cost split, context sizes, what fills the context, and the 5-minute vs 1-hour cache trade-off.
